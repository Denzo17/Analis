# Анализ лидов — внешний виджет amoCRM

Дашборд по воронке лидов: сколько лидов пришло, сколько дошли до ключевого
этапа и до продажи, конверсии на каждом переходе, разбивка по менеджерам и
источникам, фильтры по периоду/ответственным/источникам, настраиваемый
внутри виджета дизайн.

## Как это устроено

Виджет **внешний**: вся логика, данные и вёрстка дашборда живут на нашем
собственном сервере, а не загружены файлами в сам amoCRM. В amoCRM
регистрируется только маленький «шим» — манифест + ~100 строк script.js,
который добавляет кнопку «Анализ лидов» в список сделок и по клику
открывает полноэкранный `<iframe>` на наш сервер.

**Важный нюанс**, чтобы не было сюрприза: amoCRM всё равно требует один раз
загрузить этот шим-пакет (`widget/`) через экран интеграции в личном
кабинете — так регистрируется сама кнопка/точка входа, это неизбежная часть
API amoCRM для любого виджета, внутреннего или внешнего. Разница в том, что
это делается **один раз для приложения**, а не при подключении каждого
клиентского аккаунта — установка в конкретный аккаунт идёт через обычный
OAuth-флоу (клиент жмёт «Установить», дальше всё работает через API, без
какой-либо повторной загрузки файлов).

```
backend/    Node.js + Express: OAuth, хранение токенов (SQLite), запросы к
            /api/v4 amoCRM, агрегация воронки/конверсий, отдаёт фронтенд
frontend/   Дашборд внутри iframe: фильтры, KPI-плитки, воронка, таблицы,
            панель настроек — всё на чистом JS/HTML/CSS, без сторонних
            чарт-библиотек
widget/     Шим для amoCRM: manifest.json + script.js + style.css + i18n —
            загружается один раз в личном кабинете разработчика amoCRM
```

## 1. Создать интеграцию в amoCRM

1. В нужном amoCRM-аккаунте: **Настройки → Интеграции → Создать интеграцию**.
2. Тип — «Виджет» (это тот самый шим; данные при этом всё равно тянутся с
   нашего сервера через API, аккаунт клиента ничего руками не грузит).
3. Заполните:
   - **Ссылка для перенаправления** (redirect URI) — `https://ваш-домен/oauth/callback`
     (тот же адрес, что будет в `AMO_REDIRECT_URI`).
   - Остальные поля (название, описание) можно списать из `widget/i18n/ru.json`.
4. Сохраните — amoCRM выдаст **Integration ID (client_id)** и **Секретный
   ключ (client_secret)**. Впишите их в `.env` (см. ниже) и в
   `widget/manifest.json` → `widget.secret_key`.
5. На вкладке загрузки файлов виджета — соберите `widget/` в zip
   (manifest.json, script.js, style.css, i18n/, images/) и загрузите. Это
   тот самый одноразовый шаг регистрации кнопки.
6. Перед публикацией на реальном аккаунте откройте `widget/script.js` и
   замените `BACKEND_URL` на адрес задеплоенного бэкенда.

## 2. Настроить и запустить бэкенд

```bash
cd backend
npm install
cp ../.env.example ../.env   # заполните AMO_CLIENT_ID / AMO_CLIENT_SECRET / AMO_REDIRECT_URI / APP_BASE_URL / SESSION_JWT_SECRET
npm start
```

По умолчанию хранилище — файл SQLite (`DB_PATH`, по умолчанию
`backend/data/app.sqlite`) с токенами по аккаунтам и настройками дашборда.
Отдельная СУБД не нужна — файла достаточно даже под несколько сотен
аккаунтов; в README ниже — куда это можно задеплоить.

## 3. Подключить аккаунт клиента

В самом amoCRM-аккаунте на странице установленной интеграции клиент жмёт
**«Установить»** → amoCRM сам уводит браузер на `AMO_REDIRECT_URI` с кодом
авторизации → бэкенд обменивает код на токены и сохраняет их
(`/oauth/callback` в `backend/src/routes/oauth.js`). После этого кнопка
«Анализ лидов» в списке сделок открывает дашборд.

## Где задеплоить (бюджетный российский хостинг)

Нужен обычный VPS с Node.js 18+ (оплата картой РФ), например **Timeweb
Cloud**, **Selectel** или **Рег.ru VPS** — самый дешёвый тариф (1 vCPU/1–2
ГБ RAM) с запасом тянет этот сервис, т.к. вся тяжёлая агрегация идёт
запросами к API amoCRM, а не локально. Поставьте домен с HTTPS (Let's
Encrypt через `certbot` или `Caddy`), пропишите его в `APP_BASE_URL`,
`AMO_REDIRECT_URI` и `widget/script.js`. Управляйте процессом через `pm2`
или systemd-юнит.

## Настройка виджета внутри дашборда

Ключевой этап и этап продажи выбираются вручную на панель «Настройки
виджета» внутри самого дашборда (не в модалке amoCRM) — отдельно для каждой
воронки. Там же настраивается акцентный цвет и какие плитки/блоки
показывать. Пока не выбраны оба этапа для воронки, дашборд показывает
приглашение их настроить вместо данных.

## Известные ограничения / что стоит проверить перед продакшеном

- **Логика «дошёл до этапа»** — приближённая: считается по текущему статусу
  сделки (её позиции в порядке этапов воронки), а не по полной истории
  переходов. У сделки, помеченной «Не реализовано», не сохраняется, до
  какого этапа она успела дойти без отдельного запроса истории событий по
  каждой сделке — это дорого делать для всего аккаунта на каждую загрузку
  дашборда, поэтому такие сделки считаются только в «Новых» и в «Отказе».
  Подробности — комментарий в `backend/src/services/leadsAnalytics.js`.
- **Проверка запроса от виджета** — сейчас бэкенд доверяет
  `account_id`/`subdomain` из iframe, только если для этого аккаунта уже
  есть сохранённые OAuth-токены (реальное доказательство, что аккаунт
  прошёл установку). Для более строгой проверки конкретно этой сессии
  amoCRM отдаёт виджетам через `self.system()` дополнительное значение для
  подписи запроса — прежде чем открывать виджет большому числу аккаунтов,
  стоит свериться в DevTools на живом тестовом аккаунте (как это уже
  сделано для `TAG_RULES` в соседнем виджете teg_paint) и дописать проверку
  в `backend/src/middleware/session.js`.
- **Расположение кнопки** — `widget/manifest.json` сейчас регистрирует
  локацию `llist-0` (тулбар списка сделок). Проверьте в интерфейсе
  amoCRM после первой загрузки, устраивает ли расположение кнопки, и при
  необходимости добавьте другие локации (полный список — на экране
  настройки виджета в личном кабинете разработчика).
- **Источники лидов** — берутся из `/api/v4/sources` (диджитал воронка) и
  встроенного `with=source` у сделки. Если в аккаунте источники ведутся
  через кастомное поле, а не через диджитал воронку, нужно будет добавить
  отдельную ветку в `backend/src/services/leadsAnalytics.js`.
