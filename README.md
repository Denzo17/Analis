# Анализ лидов

Дашборд по воронке лидов: сколько лидов пришло, сколько дошли до ключевого
этапа и до продажи, конверсии на каждом переходе, разбивка по менеджерам и
источникам, фильтры по периоду/ответственным/источникам, настраиваемый
внутри самого дашборда дизайн.

## Как это устроено

Данные и вёрстка дашборда живут на собственном сервере (Node.js/Express),
который через OAuth подключается к amoCRM API и сам считает воронку.

**Доступ к дашборду — отдельная страница `https://ваш-домен/dashboard`**,
защищённая паролем, а не кнопка внутри интерфейса amoCRM. Изначально
задумывалась кнопка/iframe прямо в amoCRM (файлы для этого лежат в
`widget/` и рабочие), но приватные интеграции, которые сейчас можно
создать в личном кабинете amoCRM (Настройки → Интеграции → Создать
интеграцию), дают только OAuth/API-доступ — без отдельной вкладки для
загрузки manifest.json/script.js, через которую раньше регистрировалась
кнопка в интерфейсе. Если такая возможность в вашем аккаунте появится
(другой тип интеграции, партнёрский доступ к маркетплейсу и т.п.) — файлы
из `widget/` можно будет использовать без переделок, точка входа
`/widget` в бэкенде для этого уже есть.

```
backend/    Node.js + Express: OAuth, хранение токенов (SQLite), запросы к
            /api/v4 amoCRM, агрегация воронки/конверсий, отдаёт фронтенд,
            страницу входа /dashboard
frontend/   Сам дашборд: фильтры, KPI-плитки, воронка, таблицы, панель
            настроек — всё на чистом JS/HTML/CSS, без сторонних чарт-библиотек
widget/     Задел на будущее: manifest.json + script.js для встраивания
            кнопки в интерфейс amoCRM, если/когда такая возможность
            появится (см. выше)
```

## 1. Создать интеграцию в amoCRM

1. В нужном amoCRM-аккаунте: **Настройки → Интеграции → Создать интеграцию**.
2. Заполните:
   - **Ссылка для перенаправления** (redirect URI) — `https://ваш-домен/oauth/callback`
     (тот же адрес, что будет в `AMO_REDIRECT_URI`).
   - Название/описание — на ваше усмотрение.
3. Сохраните — на вкладке **«Ключи и доступы»** появятся **ID интеграции**
   (это `client_id`) и **Секретный ключ** (это `client_secret`). Впишите их
   в `.env` (см. ниже).

## 2. Настроить и запустить бэкенд

```bash
cd backend
npm install
cp ../.env.example ../.env   # заполните AMO_CLIENT_ID / AMO_CLIENT_SECRET / AMO_REDIRECT_URI / APP_BASE_URL / SESSION_JWT_SECRET / DASHBOARD_PASSWORD
npm start
```

По умолчанию хранилище — файл SQLite (`DB_PATH`, по умолчанию
`backend/data/app.sqlite`) с токенами по аккаунтам и настройками дашборда.
Отдельная СУБД не нужна.

## 3. Подключить аккаунт

В самом amoCRM-аккаунте на странице интеграции (шаг 1) нажмите
**«Установить»** → amoCRM уводит браузер на `AMO_REDIRECT_URI` с кодом
авторизации → бэкенд обменивает код на токены и сохраняет их
(`/oauth/callback` в `backend/src/routes/oauth.js`).

## 4. Открыть дашборд

Перейдите на `https://ваш-домен/dashboard`, введите пароль из
`DASHBOARD_PASSWORD`. Если подключён ровно один аккаунт — дашборд
откроется сразу; если несколько — сначала появится список для выбора.
Ключевой этап и этап продажи настраиваются вручную на панели «Настройки
виджета» внутри самого дашборда — отдельно для каждой воронки. Пока не
выбраны оба этапа, вместо данных показывается приглашение их настроить.

## Где задеплоить (бюджетный российский хостинг)

Нужен обычный VPS с Node.js 18+ (оплата картой РФ), например **Beget
Cloud** — самый дешёвый тариф (1 vCPU/1–2 ГБ RAM) с запасом тянет этот
сервис, т.к. вся тяжёлая агрегация идёт запросами к API amoCRM, а не
локально. Нужен домен с публичным IPv4 и HTTPS (Let's Encrypt через
`certbot`). Управляйте процессом через `pm2` (`pm2 start src/server.js
--name leads-analysis`) или systemd-юнит.

## Известные ограничения / что стоит проверить перед продакшеном

- **Логика «дошёл до этапа»** — приближённая: считается по текущему статусу
  сделки (её позиции в порядке этапов воронки), а не по полной истории
  переходов. У сделки, помеченной «Не реализовано», не сохраняется, до
  какого этапа она успела дойти без отдельного запроса истории событий по
  каждой сделке — это дорого делать для всего аккаунта на каждую загрузку
  дашборда, поэтому такие сделки считаются только в «Новых» и в «Отказе».
  Подробности — комментарий в `backend/src/services/leadsAnalytics.js`.
- **Пароль дашборда** — единственная защита страницы `/dashboard`
  (`DASHBOARD_PASSWORD`), т.к. страница открывается вне сессии amoCRM и
  никак не привязана к её авторизации. Никому не давайте прямую ссылку
  вместе с паролем без необходимости; при желании усилить — можно добавить
  Basic Auth на уровне nginx поверх этого пароля.
- **Источники лидов** — берутся из `/api/v4/sources` (диджитал воронка) и
  встроенного `with=source` у сделки. Если в аккаунте источники ведутся
  через кастомное поле, а не через диджитал воронку, нужно будет добавить
  отдельную ветку в `backend/src/services/leadsAnalytics.js`.
